# Phase 3 설계

기존 Product/Item 버전, 데이터 출처, 익명 지갑, 트랜잭션 구매 구조를 유지하고 공식 보상 정의를 추가했다. 실제 개봉·추첨·선수 지급 엔진은 없다.

## 저장 구조

- SourceSnapshot: DatasetVersion, URL, 수집/검증 시각, 수집 방식, 접근 한계, 본문 및 해시.
- ProductVersion: 필드별 검증 상태, 판매 기간, 상품 근거 스냅샷.
- ItemVersion: rewardBehavior, 원문 조건, 버전별 RewardPoolVersion 연결.
- RewardPoolVersion: 버전, DatasetVersion, 근거 스냅샷, 행동, 원문 조건/유효 기간, 검증 상태, 분모·합계·허용 오차.
- ProbabilityEntry: 순서, 원문 확률, 정밀 분자, 수량, 원문 조건, NESTED_ITEM / PRICE_RANK / BP_AMOUNT 대상.

타입과 지급 행동은 분리한다. 현재 필요한 UNKNOWN, FIXED, ALL, WEIGHTED_RANDOM, PLAYER_POOL만 구현했다. 상품은 ProductComponent로 직접 구성품에, 중첩 아이템은 ItemComponent 및 보상 대상 FK로 연결한다. 순위형 보상에는 선수 ID를 만들지 않는다.

Migration: `prisma/migrations/202609200001_reward_definitions/migration.sql`. 정밀 값은 Decimal(40,0), BP는 Decimal(30,0)이다. FK·순서 유일성·수량 양수·대상 형태·확률 범위 제약을 추가했다.

## 확률 정밀도와 검증 정책

백분율의 소수점 이하 최대 18자리를 BigInt로 파싱한다. 백분율 단위 스케일은 10^18, 확률 분모는 10^20이다. 예를 들어 `0.1250%`는 분자 125000000000000000 / 분모 100000000000000000000으로 저장하고 원문도 별도로 유지한다. 확률에 JavaScript Number 연산을 사용하지 않는다.

합계 검증은 표기 마지막 자리 단위와 15자리 유효숫자 단위 중 큰 값을 각 행의 quantum으로 삼는다. 공식 본문에는 소수 16자리로 채워져 있지만 실질적으로 15자리 유효숫자인 값이 있어 적용한 명시적 검증 정책이다. 행별 quantum의 합을 절반으로 올림한 오차까지 허용하되 최대 **0.05 퍼센트포인트**로 제한한다. 실제 미공개 확률 정밀도를 안다고 가정하는 것이 아니며, 수치를 100%로 재분배하거나 원문을 수정하지 않는다. 허용 오차도 DB에 저장한다.

FIXED는 한 행의 100%, ALL은 모든 행 각각 100%이어야 한다. WEIGHTED_RANDOM/PLAYER_POOL은 합계와 오차를 검사한다. 음수·100% 초과·지수 표기·지원하지 않는 형식·빈 보상·중복·누락 대상/출처·불완전 순위·순환·도달 불가능 노드·깊이 초과는 거절한다.

## Import

`npm run data:validate`는 DB 없이 전체 데이터를 검증한다. `npm run db:import:official`은 검증 후 하나의 트랜잭션으로 저장한다. `npm run db:seed`는 기존 MOCK 및 FC 옵션과 공식 상품을 함께 준비한다.

저장 본문/선택 manifest → Zod → 출처 허용 목록 및 해시 → 표 파싱 → 상품 목록/상세의 가격·구성·수량 교차 확인 → 정밀 확률 및 그래프 검증 → immutable DatasetVersion → DB 순서다. 지원하는 공식 표 형식이 바뀌면 추측하여 계속하지 않고 실패한다. 범용 자동 크롤러가 아니다.

동일 버전·동일 importHash 재실행은 no-op이다. 같은 버전을 다른 본문으로 덮어쓰면 거절한다. 갱신은 원문을 다시 확인하고 새로운 버전으로 준비해야 한다. 실패한 입력은 게시 중인 데이터셋을 덮어쓰지 않는다.

## 조회와 UI

기존 상품 API의 구성품 그래프를 확장하고 별도의 중복 reward-tree API는 만들지 않았다. `GET /api/items/[id]/probabilities?page=1`은 **ItemVersion ID**를 받는다. 한 페이지 50행이며 750행 표는 15페이지다. 범위 밖 페이지·없는 정의는 404, 잘못된 입력은 400, 저장소 장애는 상세 정보 없이 503으로 처리한다.

상품 상세는 중첩 트리를 접었다 펼치고 확률 요약에서 `/items/[id]/probabilities`로 이동한다. 상세 화면에서 수백 개 보상 행을 미리 내려받지 않는다. 확률 페이지는 원문 값·수량·조건·기간·출처·검증 상태 및 수집 한계를 표시한다. 상품 이미지는 관측한 CDN의 상품 경로만 허용하고 실패 시 기존 fallback을 사용한다.

## 가상 구매

공식 데이터셋과 이름·가격·통화·구성품 검증을 서버에서 확인한다. REFERENCE와 미검증 공식 상품은 구매할 수 없다. 기존 MOCK 정책은 유지한다. 익명 세션·잔액 잠금·멱등 요청·리셋 epoch는 기존 구매 엔진을 사용한다.

공식 상품 한 번 구매 시 상자 1 / 선수팩 3 / 코인 30만 지급한다. 상자 내부 선수팩이나 BP를 즉시 지급하지 않는다. 구매/인벤토리에 OFFICIAL 출처를 유지하지만 충전 잔액과 원장은 계속 가상의 MOCK 통화다. 공식 서버 거래가 아니다.

공식의 채널별 각 3회 안내와 별개로 시뮬레이터에서는 익명 세션 리셋 전 해당 상품을 최대 3회 구매한다. 공식 판매 기간은 표시하지만 저장된 정의를 체험하는 구매에 현재 판매 상태를 자동 적용하지 않는다. 실제 계정/채널 구매 이력이나 판매 상태를 동기화하지 않는다.

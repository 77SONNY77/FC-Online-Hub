# Phase 2 — Reference verification

확인일: 2026-09-19 (KST). 공개 페이지를 읽고 브라우저에서 탭을 전환했습니다. 로그인, 실제 구매, 결제 요청은 하지 않았습니다. 아래는 해당 시점의 관찰이며 지속적으로 최신 옵션을 보장하는 자동 수집은 아닙니다.

## FC Online Web Shop

출처: https://shop.fconline.nexon.com/

정적 응답만으로 판단하지 않고 실제 Chromium에서 **FC 구매** 탭을 열었습니다. 일반 FC와 멤버십 할인 FC가 구분되고, 카드에서 기본 수량·추가 FC·총 수량·CASH 가격을 읽을 수 있었습니다. 상단 상점 분류, 보유 재화 주변 충전 진입점, 상품 카드 그리드와 구매 진입 구조를 참고했습니다.

일반 FC 화면에서 확인한 수량:

| 기본 FC | 추가 FC | 총 FC |
|---:|---:|---:|
| 300 | 0 | 300 |
| 500 | 10 | 510 |
| 1,000 | 40 | 1,040 |
| 3,000 | 180 | 3,180 |
| 5,000 | 400 | 5,400 |
| 10,000 | 1,000 | 11,000 |
| 20,000 | 2,400 | 22,400 |

이 수량만 `official-fc-units-20260919`로 저장했습니다. 기본 수량과 추가 수량을 각각 보여주고 버튼은 지급될 **총 FC**를 안내합니다. 따라서 10,000 FC 카드는 1,000 추가 FC를 포함하여 11,000 가상 FC를 지급합니다.

공식 현금 가격, 멤버십 할인 자격, 쿠폰, 판매 조건을 시뮬레이터 정책으로 가져오지 않았습니다. 결제창·PG·Nexon Cash API도 없습니다. 원본 이미지·소스·스타일시트는 복사하지 않았고 FC 동전과 아이템 그림은 CSS/자체 SVG입니다.

`OFFICIAL`은 **참고한 수량 데이터의 출처**입니다. 시뮬레이터의 잔액·원장·구매·보유품은 항상 `MOCK`으로 구분합니다. 공식 상품 카탈로그는 여전히 0종입니다.

## FC Detox

출처: https://fcdetox.com/ 및 https://fcdetox.com/open/44699

공개 상품 선택 화면과 상세 시뮬레이션 화면을 다시 확인했습니다. 로그인 없이 진입할 수 있고, 수량 조절(증감 및 큰 단위 증가), 가격·사용 FC·보유 수량을 행동 버튼 근처에서 확인하는 흐름을 관찰했습니다. 상품 선택 후 바로 시뮬레이션하는 낮은 진입 장벽을 참고했습니다.

적용: 설명 화면이나 계정 생성 없이 상점에서 시작, 상단 공통 잔액, 상세 내 수량/총 비용/부족한 FC 안내, 완료 직후 인벤토리 링크. FC Detox의 개봉 기능·확률·선수 결과·코드는 이번 구현에 가져오지 않았습니다.

## Independent implementation decisions

- 최초 잔액 0. 충전 옵션 클릭만으로 무료 가상 지급, 토스트로 완료 안내.
- 상점 / FC 구매 / 인벤토리만 활성 메뉴로 표시.
- 작은 개발용 데이터 배지와 공식 출처 링크로 데이터 성격 표시.
- 파운데이션 상품 한도 5개는 서버 동시성 검증을 위한 개발용 규칙. Phase 1의 미확인 공식 구매 제한 필드를 덮어쓰지 않고 별도 `PurchasePolicy`로 관리.
- 상자는 직접 구성품 수량만 지급. 내부 보상은 지급하지 않음.
- 브라우저 상태 식별자는 UI에 노출하지 않음.
